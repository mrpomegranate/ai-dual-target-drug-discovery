# M1.5 — Source imbalance, potency distributions and confounding diagnostics

**Project:** AI Dual-Target Drug Discovery (EGFR/HER2)
**Date:** 2026-10-31
**Status:** Completed as **descriptive** observation-level diagnostics; source-bias causality is **not** established.
**Input:** M1.4's 35,210-row EGFR/HER2 observation CSV.

## Scientific question

Do different **BindingDB curation-source categories** contribute different proportions of target observations, target-construct annotations, measured potencies, active/inactive bounds, repeated reported compounds and available assay metadata? These imbalances can confound model interpretation, especially if chemistry, target construct and study source are correlated.

The `source` field denotes a curation/data-source category (e.g. `US Patent` or `ChEMBL`); **it does not uniquely identify a laboratory**. A source-specific difference is not automatically laboratory measurement bias.

## Exact-value potency summary (unadjusted)

| Target | ChEMBL median pIC50 | US Patent median pIC50 | Difference (patent − ChEMBL) |
|---|---:|---:|---:|
| EGFR | 7.0414 | 7.8356 | +0.7942 |
| HER2 | 6.8928 | 7.3909 | +0.4981 |

Medians above use **exact IC50 only**. They are **unadjusted** group summaries: the sources do not necessarily test the same compounds, protein variants, conditions or assay protocols. They must not be interpreted as source-specific assay error or model performance.

## Target-name annotation diagnostic and subsequent correction

The initial `02_construct_annotations_by_source.png` flags only target names containing a **square bracket** (`[`). Under that strictly defined rule:

- EGFR US Patent: `7,722 / 14,274` (**54.10%**); EGFR ChEMBL: `0 / 13,316`.
- HER2 US Patent: `1,257 / 3,364` (**37.37%**); HER2 ChEMBL: `2 / 2,479` (**0.08%**).
- WIPO EGFR: `327 / 339` (**96.46%**).

**Important update from M1.6:** 100 additional EGFR US Patent observations use a **parenthetical** notation, such as `(EGFR)(L858R)(T790M)`, rather than square brackets. The initial M1.5 metric is therefore named **bracket annotation percent**, not total construct-annotation percent. The later `08_construct_name_categories_by_source.png` is the preferred expanded diagnostic; it distinguishes substitutions, mixed constructs and other annotations. Neither notation verifies actual protein sequence or proves that an unannotated name is wild-type.

## Provenance and metadata caveats

- Article DOI, PMID and patent-number availability varies strongly by source. Patent records naturally have patents rather than PMIDs, so comparisons of individual field completeness need context.
- pH and temperature metadata are sparse for several sources. Missing protocol fields prevent full adjustment for assay conditions.
- The same reported InChIKey can occur across different source rows or target constructs. Counts are not yet molecule-standardized or assay-deduplicated.
- Censored IC50 observations are excluded from the exact-pIC50 boxplots but retained where the activity inequality gives a definite classification.

## Reproduce (PowerShell)

The plotting dependency may already be installed; if not:

```powershell
uv add --dev matplotlib
```

From the repository root:

```powershell
uv run --locked python .\scripts\plot_source_bias.py `
    --input .\data\interim\bindingdb_egfr_her2_observations.csv `
    --outdir .\reports\figures\source_bias `
    --summary .\reports\audits\M1_5_source_bias_profile.json
```

Open the gallery:

```powershell
Start-Process .\reports\figures\source_bias\index.html
```

The JSON records a SHA-256 of the exact observation CSV used for plotting. The user's previously shared M1.5 JSON reported `5579aa3d6d4ceb66f0b23cb3803e1978c54c212206e33e50cd0658ebcd6b52e3`, while an uploaded corrected M1.4 CSV later had `cc4757fe64b3a2ace4b183ad477d0bdaab9ad609ac82267bc4eb5ed1e5e84339`. The record counts coincide, but **the source bytes differ**. For a consistent final evidence chain, rerun M1.5 on your current corrected M1.4 CSV and retain the regenerated profile's `input_sha256`.
